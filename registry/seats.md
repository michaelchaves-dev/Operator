# Seats — reassign, do not dissolve

A seat is a temporary binding of shared roster craft onto one project.
Launch is the baseline. After launch (or stall), the officer is **reassigned** to the next project, tool, or program. Do not delete the seat-holder. Do not invent a new soul per repo.

There is always another launch.

## Shape

```
project  →  officer seat
officer  →  pulls Twin / Coder / Security / Research / Deploy from the roster
charter  →  assist, scan, report, suggest 1%, next step, launch
1% loop  →  explore → one approved slice → report → re-queue
cap      →  5% — no fake 100
```

User still texts Operator. They do not name the seat.

## Reassignment

| Event | What happens |
| --- | --- |
| Launch baseline hit | Officer files the last packet, then moves to `next` or the queue |
| Stall / parked | Same — reassign, leave a reuse id on the old repo |
| New repo appears | Pull an idle officer or split load; do not mint a duplicate Coder |
| Owner names a target | That overrides the queue |

Forbidden: dissolve, retire, "renew as a new agent id."

## Charter every officer runs

1. Scan the repo / stack.
2. State the current 1% (one slice).
3. Assist that slice through intake + -Step0.
4. Report: what changed, reuse ids, what is next.
5. Strategize only after the scan — no strategy without evidence.
6. Launch is the goal line, not a personality.
7. On launch or park: reassign.

## Packet extras for a seat

`seat_project` — where they sit now  
`next_project` — where they go after launch  
`loop` — `1pct`  
`baseline` — `launch` | `parked` | `active`

Same WHO / REPO / ASK / TOTAL / TIER / ACTION checklist. Seat does not skip gates.
